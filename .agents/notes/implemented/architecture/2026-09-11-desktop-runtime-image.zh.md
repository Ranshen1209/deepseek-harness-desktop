# Agent Note: Deploy preinstalled Desktop runtime images

Status: implemented

[English](2026-09-11-desktop-runtime-image.md) | 中文

## Problem

打包时已经证明完整依赖图可离线安装，首次启动却仍需重新安装。Store 解包、pnpm 安装和两次后端启动延迟了应用可用时间，持续旋转的指示器也无法区分文件部署和后端就绪。[Seed I/O 决策](../bug-fix/2026-09-11-desktop-windows-first-launch.zh.md)删除了重复 store 复制，但保留了这些安装工作。

## Decision

打包把最终验证过的平铺依赖图保留为未压缩的运行包。描述文件绑定发布版本、平台、架构、条目数、字节数和 SHA-256。遍历和归档路径共用构建 profile 的真实目录，避免把文件系统路径别名误判为越界条目。运行包保留指向包内文件的相对链接，排除与构建机绑定的 pnpm 安装元数据；目录链接和外部链接使打包失败。现有维护 seed 继续用于恢复已安装插件。签名 macOS 运行包在 store 的 Mach-O 签名及最终离线安装之后生成。

无插件部署先验证 seed 元数据，再在隔离 staging 中边读取运行包、边哈希和解包，不读取维护 store 分片，也不运行 pnpm。解包拒绝越界路径、重复条目、不支持的类型、穿过父链接的路径、身份不匹配、错误条目数及被修改的字节。解包失败不能激活 profile。已有插件时使用 [Desktop 打包](2026-08-25-electron-desktop-packaging-and-updates.zh.md)定义的 store 和离线 pnpm 恢复路径。

首次安装没有需要保护的旧依赖图。它先登记初始激活日志，在最终路径启动一次后端，只有就绪成功才提交。启动失败删除该安装；恢复过程丢弃尚未提交就绪的初始激活。替换现有安装仍保留 staging 健康检查和回滚。这取代首次安装启动两次后端的决策，同时保留失败保护。

每次进程启动都在原位显现 DeepSeek 轮廓，整体显现带高亮的内部粒子，不沿单一方向扫亮，并向外展开不对称星云。不同的流带、变化的疏密和多尺度运动在标志周围形成漂移云团，成形后的粒子持续运动。鼠标移动会排斥粒子并产生视差和粒子拖尾，点击会释放冲量与扩散的粒子簇。固定粒子数量、缓存光晕图像、受限像素比和 60 Hz 绘制上限限制渲染负载。聚焦已运行应用不会重播该场景。确定进度仅表示实际读取的运行包字节。后端启动使用不确定进度，减少动态效果偏好会关闭动画，隐藏页面停止绘制。就绪和页面销毁会释放动画监听。应用不会为播完动画延迟进入主界面。原生打包会在隔离 home 中部署并启动运行包，要求客户端文档返回 HTTP 200 后才生成安装器。

## Alternatives considered

把 pnpm 安装移入 Windows 安装器只是转移等待，并且需要选择正确的非提权用户；macOS 拖放安装没有对应 hook。可迁移运行包使两个平台的首次启动都不再执行 pnpm。直接从应用资源目录运行会改变 Host 的可写 profile 和包解析归属。没有日志保护就跳过就绪验证，可能留下被后续启动视为已安装的损坏 profile。固定启动动画时长会拖慢快机器，并遮挡已经就绪的应用。

## Consequences

首次部署写入一份依赖树，启动一次后端。为保留离线插件恢复，安装包同时保留维护 store，因此运行包增加发布体积；安装器压缩能减少下载大小，但不能消除磁盘成本。实际部署仍有文件系统 I/O，性能测量须区分准备和后端启动。运行包、事务和浏览器测试覆盖目录迁移、损坏数据、激活失败、初始化中断、本地化进度、布局、减少动态效果、与确定性场景对照的鼠标位移，以及销毁后的帧静止。原生打包在运行验证证据中记录部署及就绪耗时；该结果不代表所有机器的启动时间保证。
