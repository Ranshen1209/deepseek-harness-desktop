# Agent Note: 桌面原生权限与逐次 Auto

Status: implemented

[English](2026-09-18-desktop-native-auto-approval.md) | 中文

## Problem

全局 Auto 拦截重命名了原生选项却没有恢复行为，并因不存在独立执行器而在看似有用的批准后整类封禁命令。Agent 因而可能写入成功却无法验证。人工批准与实际执行需要共享同次调用的授权归属。

## Decision

桌面保留原生三档，使用 preservation 作为 Auto。[实验性 Web Auto](../feature/2026-08-28-auto-review.zh.md) 仍是独立选装集成，具有自身语义，本决策不替代它。桌面复用原生工作区写入沙箱加模型逐次审查，并明确 Windows 部分保护限制。普通 Shell、安装、构建、测试及有界文件搜索保持可用。模型拒绝不弹窗；建议执行的扩权调用需一次人工决定，不产生会话级完全权限。

准备阶段捕获真实提供者、解析后的进程参数、环境、工作目录和适用文件版本。工具和扩权校验共享同一调用记录；原生执行器在隔离准备后核验并于启动前消费一次。Host 生命周期检查在等待、切模式和插件重载时保留原 Auto 归属；原生调用绕过 Auto。不一致的旧权限选择等待明确重选，不扩大授权。

创建事实来自已核实文件提交，跨获准编辑仍绑定当前 Agent 和版本。搜索将核实的内容快照交给本地搜索进程，避免其重新打开被审核路径。普通脚本效果依赖原生沙箱，不能因存在结构化回收工具就获得可恢复性。

搜索能力属于 Agent 作用域内的工具定义。Auto 捕获定义及执行函数，并在派发前拒绝替换。从 Agent 预设发布进程全局标记会阻止预设挂载，也不能证明另一个 Agent 的搜索实现。预设隔离检查继续生效。工作区连接失败保留原工作区和草稿，展示实际错误，且不能清除更新的选择请求。

只有 Host 审批服务向 Electron 主进程发送类型化等待/结束消息。原生通知仅透露通用操作类别，以请求身份去重并导航到仍待确认的卡片，不能授权执行。已停止 Host 代次和已结束请求使旧点击失效；通知失败保留应用状态。

## Alternatives considered

**所有命令先要求新独立代理。** 本版没有这一代理，封禁正常构建与验证无法满足已选择的可用性目标。

**将模型审查或命令正则当成隔离。** 二者都不能约束实际文件、进程和网络效果，界面与文档保留原生后端的真实限制。

**复用完全权限或全局 Auto 接管。** 这会合并用户的不同选择，使切模式或旧设置静默改变执行授权。独立模式与精确单次扩权保留用户意图。

## Consequences

Auto 可以审核常规 Agent 任务，不要求人类逐项枚举文件名。Windows 任意代码执行仍受原生沙箱能力限制，模型也可能误判。结构化文件保护和单文件可恢复移除不意味着脚本删除可恢复，也不能消除全部系统发布竞态。运行期文件认领不在重启后变成持久授权。

定向文件/搜索、权限迁移、审批生命周期、通知和原生启动协议测试不使用真实模型。工作区选择另在本机最终打包的 Electron 界面中使用独立 Profile 检查，该检查不代表模型任务或审批按钮通过。真实模型规划、实际审批按钮、Windows 10/11 通知、VM 运行及真实用户 Profile 升级由用户验收。延后任务验收的未签名本地包属于候选，不能宣称端到端通过。[桌面 README](../../../../apps/desktop/README.zh.md#user-run-acceptance) 维护可复现验收步骤。
